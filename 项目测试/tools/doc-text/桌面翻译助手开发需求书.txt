# 桌面翻译助手需求说明书（基于 DeepSeek Harness）v2
## 1. 项目概述
开发一款 Windows/macOS 桌面翻译软件，以 DeepSeek Harness 为后台编排引擎，实现屏幕指定区域的文字识别与翻译。软件以透明浮窗形式常驻桌面，支持**离线免费翻译（默认）** 与**用户自选 AI API 联网翻译**双模，工作时（看视频、打游戏、全屏应用）不遮挡内容、不抢焦点，实现无感实时翻译。
**核心定位**：软件本身零翻译费用——离线层内置开源翻译模型，联网层由用户自行配置 API Key，软件不内置、不承担任何付费 API 成本。
## 2. 功能需求
### 2.1 软件形态与部署
| 编号 | 需求 | 说明 |
|------|------|------|
| F-01 | 独立桌面软件 | 产出可独立安装的 `.exe`（Windows）与 `.dmg`（macOS），最终用户无需安装 Node.js、Git 等开发环境。封装路径在 Tauri、WebView2 壳、Electron 三者中择一，V1 建议优先评估 Tauri（体积小、社区已有 DSH 打包方案）。 |
| F-02 | 系统托盘驻留 | 主窗口关闭时最小化至托盘，不退出进程；托盘菜单提供展开浮窗、框选区域、设置、退出。 |
| F-03 | DSH 作为后台引擎 | DeepSeek Harness 运行在后台，承担 OCR 与翻译流水线的编排职责，不直接作为用户交互界面。浮窗为独立窗口，通过 IPC 或本地 HTTP 接收 DSH 插件产出的翻译结果。 |
### 2.2 翻译能力（离线默认 + 联网用户自选）
| 编号 | 需求 | 说明 |
|------|------|------|
| F-04 | 离线翻译（默认，开箱即用） | 内置腾讯混元 **HY-MT1.5-1.8B** GGUF 量化模型，通过 llama.cpp 本地推理，支持 33 种语言互译。量化后约 1GB 内存占用，50 tokens 平均约 0.18 秒。零网络依赖、零费用，即使用户不配置任何 API 也完全可用。 |
| F-05 | 联网翻译（用户自选 AI API） | 提供 AI API 配置面板，用户自行填入 API Key、Base URL、模型名称，支持任意 OpenAI 兼容接口。软件**不内置任何付费 API 密钥**，联网翻译费用由用户自行承担。配置面板预置 DeepSeek、OpenAI、Claude、Gemini 等常见服务的模板以降低填写门槛。 |
| F-05a | 多 API 优先级与故障转移 | 用户可配置多个 API，按排序形成主用→备用链：卡片式配置，上下移动调整顺序，每个卡片带启用开关与“测试连接”按钮。调用时按顺序串行尝试，第一个返回有效译文即采用；超时或报错则尝试下一个；全部失败回退离线引擎。**fallback 触发条件为调用失败或超时，不包含质量评估**。单次请求超时建议 5 秒，备用 API 可缩短至 3 秒，最多串行尝试 2 个以避免延迟累积。 |
| F-06 | 自动降级 | 联网请求失败/超时后静默回退至混元离线翻译，浮窗标注当前翻译模式（如“DeepSeek”或“离线模式”），用户无感知中断。 |
| F-07 | 语种设置 | 源语言支持“自动检测”，目标语言手动指定；语种列表覆盖中、英、日、韩等主流语言及常用小语种。 |
| F-08 | API Key 安全存储 | 用户填入的 API Key 需加密存储于本地，不以明文落盘，不上传任何服务器。 |
### 2.3 屏幕区域翻译
| 编号 | 需求 | 说明 |
|------|------|------|
| F-09 | 框选翻译区域 | 快捷键（如 `Ctrl+Shift+T`）进入框选模式，鼠标拖拽绘制矩形区域，坐标持久化作为固定输入源。 |
| F-10 | 区域 OCR | 对框选区域截图后执行 OCR。离线建议 Tesseract（中英文）或 RapidOCR；联网可选云端 OCR 作为可选回退。 |
| F-11 | 刷新模式 | 支持**定时轮询**（如每 2 秒重新截取识别翻译）与**手动触发**（快捷键立即刷新）两种模式，看视频/游戏场景建议定时模式。 |
| F-12 | 译文浮窗显示 | OCR 文本经翻译后以半透明浮窗显示于框选区域附近或固定位置，支持滚动查看历史译文。 |
### 2.4 浮窗与“不占屏幕”设计
| 编号 | 需求 | 说明 |
|------|------|------|
| F-13 | 透明无边框浮窗 | 浮窗背景透明或半透明，无标题栏，不遮挡底层内容。 |
| F-14 | 点击穿透 | 浮窗默认不接收鼠标事件，点击穿透至下层应用；仅鼠标悬停于浮窗交互控件时恢复接收。 |
| F-15 | 始终置顶 | 浮窗保持在其他窗口之上，包括全屏视频窗口。 |
| F-16 | 收起/展开 | 浮窗可一键收起为悬浮球/小图标，点击恢复展开。 |
| F-17 | 不抢焦点 | 浮窗显示/更新译文时不夺取当前活动窗口的键盘焦点。 |
## 3. 技术架构要点
### 3.1 分层架构
```
┌─────────────────────────────────────────┐
│  浮窗 UI（独立窗口，Tauri/Electron 管理）  │  ← 点击穿透/置顶/收起
├─────────────────────────────────────────┤
│  DeepSeek Harness（后台编排引擎）          │
│   ├─ OCR 插件（截图 → 文本）              │
│   ├─ 翻译插件（离线混元 / 联网用户 API）    │
│   └─ 调度循环（定时触发流水线）            │
├─────────────────────────────────────────┤
│  本地推理后端（llama.cpp + 混元 GGUF）     │
└─────────────────────────────────────────┘
```
浮窗**不走 DSH 自带 Web UI**，由宿主壳独立管理透明窗口，通过 IPC/本地 HTTP 接收译文。DSH 的“一切皆插件”架构使 OCR、翻译器可独立替换。
### 3.2 翻译插件内部逻辑
```
输入文本 + 语种
→ 若联网模式开启且存在已启用 API：
按排序串行尝试（主用 → 备用，最多 2 个，单次超时 5s/备用 3s）
成功 → 返回译文，标注 API 名称
全部失败 → 进入离线分支
→ 离线分支：调用本地 llama.cpp 混元服务
成功 → 返回译文，标注“离线模式”
```
### 3.3 离线模型集成
混元 HY-MT1.5-1.8B 以 GGUF 量化格式随安装包分发或首次启动时下载，由 llama.cpp server 暴露 OpenAI 兼容本地接口，翻译插件直接调用，无需额外推理框架依赖。
## 4. 非功能需求
| 编号 | 需求 | 指标 |
|------|------|------|
| N-01 | 翻译延迟 | 定时模式下，截图到浮窗显示译文：联网 ≤ 2 秒（单 API 成功）；离线 ≤ 3 秒。串行 fallback 最坏情况受 F-05a 超时策略约束。 |
| N-02 | 资源占用 | 离线模式常驻内存 ≤ 1.5GB（含翻译模型）。 |
| N-03 | 游戏/视频兼容 | 浮窗不注入目标进程，仅屏幕采集，降低反作弊误判风险。 |
| N-04 | 隐私 | 离线模式全部本地处理；联网模式仅将 OCR 文本发送至用户自配置的端点，软件本身不收集、不上传任何数据。 |
| N-05 | 安装包体积 | 若模型随包分发，安装包会显著增大；建议采用首次启动下载模型的方式控制初始体积。 |
## 5. 边界与风险提示
1. **全屏独占游戏**：部分独占全屏游戏下透明浮窗可能无法显示，需引导用户将游戏设为“无边框窗口化”，此为屏幕浮窗类工具共性限制。
2. **OCR 精度**：游戏艺术字体、低对比度字幕识别率有限，译文仅供理解参考。
3. **Harness 版本稳定性**：dsh 为开发者预览版，插件 API 可能破坏性变更，建议锁定版本并做插件适配层隔离。
4. **“不占屏幕”语义**：定义为半透明、可收起、不遮挡关键内容、不抢焦点，而非物理上零占用。
5. **联网 API 质量不可控**：fallback 仅处理调用失败/超时，不判断译文质量；用户对某 API 质量不满时手动调整排序即可。
6. **免密钥公开接口不纳入 V1**：联网层完全依赖用户自配 API，软件不内置任何免密钥公共接口，避免稳定性与合规风险。
